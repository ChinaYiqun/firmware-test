# 本期评测：启动与环境

## 已准备的环境

- 独立 Python 3.12.9 环境：本目录 `.venv`。
- 已安装 EmbedEval 0.2.0 及其依赖；版本快照见 `requirements.lock.txt`。
- OpenCode 1.19.3、Claude Code 2.1.304 已可启动。
- 10 题参考实现均通过 L0/L3，检查明细见 `environment-check.json`。
- 仅准备静态评测环境；未安装 Zephyr SDK、ESP-IDF、编译/仿真环境。

## 一键启动

双击本目录 **`start.cmd`**，输入 API token（隐藏输入），即可开始预检和评测。脚本不会安装依赖，也不会更新 CLI。

也可在终端运行：

```powershell
.\start.cmd
```

如已在当前进程设置 `BENCH_ANTHROPIC_TOKEN` 或 `ANTHROPIC_AUTH_TOKEN`，无需再次输入。密钥不内置在脚本中，当前目录没有保存此前聊天中的密钥。

默认：10 题 × 两个 Harness × 1 次，共 20 个计分任务；并发 2，同 Harness 同时最多 1 个；每任务 600 秒。先顺序运行两个微型工具/权限预检（也会产生少量 API 消耗），通过后才开始计分任务。预检要求观察到越界文件读取被拒绝以及正常文件写入，失败则停止。

启动后显示任务进度条、已完成/总数、运行时间及 START / 工具事件 / DONE 日志。原始脱敏事件在每个任务的 `stdout.log`、`stderr.log`、`trace.json` 中。

```powershell
# 不调用 API：用故意错误的代码验证并发、评分和报告流程
.\start.cmd --dry-run

# 并发 4，每个 Harness 同时最多 2 个任务
.\start.cmd --concurrency 4

# 每个组合重复 3 次，共 60 个计分任务
.\start.cmd --repetitions 3

# 断点续跑：使用原来的并发、次数与时限参数
.\start.cmd --resume ".\runs\run-具体运行目录"
```

Ctrl+C 会停止任务进程树并保留已落盘结果。续跑跳过已完成评分、缺失提交和超时任务；基础设施错误和中断任务会创建新尝试。修改题目、评分源码、CLI 版本、运行器或配置后会拒绝合并续跑。

## 结果在哪

每次启动建立独立 `runs/run-时间-随机标识/`；离线模拟使用 `runs/dry-*`，报告显著标为非模型结果。

- `report.md`：通过数、已评分数、计划数、逐题状态和耗时。
- `summary.json`、`tasks.csv`：便于后续比较、分析。
- `results.sqlite`：每次尝试的结构化记录。
- `config.json`：模型、网关、版本、题目、源码哈希及实际参数，不含密钥。
- `run.log`：运行日志；`tasks/`：提交文件、评分细节、CLI 事件与历史尝试。
- `preflight/`：网关和工具权限预检记录。

静态失败、超时、缺失提交、基础设施错误分别记录。CLI 原始用量事件保留在 trace 与 result 中；当前尚未统一两家事件中的 token/cost 字段，汇总值记 null，不当作零费用。初版报告尚不包含 p95、完整按类别统计或人工误判复核。

## 当前实现边界

1. 只评 L0/L3，不能据此证明编译或硬件运行正确。
2. 使用 Harness 的文件工具权限限制，Shell、外部网络工具、子 Agent 不开放；这不是操作系统级沙箱。预检只是验证正常工具调用的边界，不能证明防御恶意 Harness。
3. 首版保留各 Harness 的默认推理策略，未验证网关实际接受的推理预算一致；属于默认策略比较。两个 Harness 的系统提示词与内部循环也不同。
4. 外部调度器不自动做网络重试；CLI 自带重试受 600 秒总时限约束。这个实现取代 PLAN 中“外部最多重试 2 次”的草案，避免重复计费和隐藏重试。
5. 首版显式指定模型并关闭外部插件、限制 provider、将辅助模型映射到同一个 ID；原始事件用于核查。不能仅凭网关模型别名或 CLI 配置证明真实后端身份。
6. 本地流程和 OpenCode 配置解析已离线验证；尚未调用两个 Harness 的模型生成接口。首次真实启动可能在兼容性/权限预检处停止，日志会保留诊断信息。

详细设计与估时见 [PLAN.md](PLAN.md)。本 README 中的“当前实现”描述优先于 PLAN 中尚未实现的设计目标。
